# 架构说明

> 中文 · [English](architecture.md)

一份简短的说明，讲清各部分如何拼装到一起。想扩展或 fork 本项目，建议先读这篇。

## 分层

```
[边缘麦克风]          [中枢服务（本仓库）]                       [被控目标]

浏览器 MediaRec   ─┐
ESP32 + INMP441   ─┼── /ws/audio ──> 音频会话 AudioSession
笔记本 sounddev   ─┘                      │
                                          ▼
                                       ASR 适配器 ── 识别文本 ──┐
                                                                ▼
                                                       意图编排器 IntentOrchestrator
                                                                │
                                                    ┌───────────┼───────────┐
                                                    ▼           ▼           ▼
                                                LLM 适配器   设备控制    路由器控制
                                                    │           │           │
                                                    ▼           ▼           ▼
                                                工具调用 ─► 状态变更 ─► SSH 命令
                                                                │
                                                                ▼
                                                           TTS 适配器
                                                                │
                                                                ▼
                                                          MP3 → 回传客户端
```

另有一个独立的 `NetworkMonitor` 任务，每隔 N 秒 ping 公网主机。连续失败达到配置的
阈值后调用恢复钩子；在 M2 阶段，该钩子会通过 TTS 语音询问，等用户说「好」之后再
SSH 重启路由器。

## 为什么到处都是适配器

每个外部依赖都坐落在一个只有极小接口（通常一两个方法）的基类后面。
`server/adapters/__init__.py` 里的工厂在启动时根据环境变量挑选一个具体实现，
其余代码永远不直接 import 任何具体服务商。

这让三件事变得很便宜：

- **换服务商**（例如阿里云 → 本地 Whisper）：新增一个适配器，再切换
  `ASR_PROVIDER=...` 即可。
- **离线测试**：`mock_*` 适配器返回预置数据。
- **空跑硬件**：`MockRouter` 只把它本应执行的 SSH 命令打到日志。

## 里程碑映射

同一套代码支持三种部署形态：

| 里程碑 | 边缘麦克风 | 服务商配置 | 真实路由器？ |
|--------|-----------|-----------|-------------|
| M0 | 浏览器 / 笔记本 | mock 或真实（自选） | mock |
| M1 | ESP32-S3 + INMP441 | 真实云端 | mock |
| M2 | ESP32-S3 + INMP441 | 真实云端 | OpenWrt SSH |

里程碑之间不改动任何代码结构——只改 `.env` 设置和你接入的硬件。

## 刻意没做的事

- **多轮对话记忆**。每次请求都是独立的，模型成本更低、也更好调试。
- **数据库**。设备状态存在内存里，重启即重置。真正需要持久化时再加一层 SQLite。
- **鉴权**。服务默认绑定 `127.0.0.1`。在加上鉴权检查之前，不要暴露到局域网。
- **服务端唤醒词检测**。浏览器用「按住说话」，ESP32 固件同样用「按住说话」。
  等整条管线稳定后，再接入 ESP-SR 或 openWakeWord。
